## 1. A11：刪除 H2 與 H4，我同意，但有兩個條件

您請我先判斷合不合理，再決定要不要照做。我的結論是**兩條都可以刪**，理由比您寫的還要更強一點。

**H2（租金梯度）：可以刪。** 您的理由是租金資料難取得、也不一定能代表正在營業的店。查證之後，問題其實更根本：租賃實價登錄只有「委由經紀業居間或代理成交」的案件才需要申報（[臺北市地政局說明](https://www-ws.gov.taipei/001/Upload/305/relfile/11455/117068/7f13d4f9-38ac-473c-8f4e-65b59963f891.pdf)）。里長又說迪化街主街店面很少經過房仲，鄰居一聽到風聲就直接接手。也就是說，公開資料會**系統性地漏掉最貴的那些店面**，就算拿到資料也會低估南北的差距。這不是資料少，而是資料有偏誤，刪掉是對的。

**H4（輪替快、老店扎根深）：可以刪。** 退場資料在時程內拿不到，而且您在 A6 已經決定主流程不做退場分析，刪掉 H4 讓整份設計前後一致。

**兩個條件（已寫進提案書）：**

1. **刪的是「檢驗」，不是「機制」。** 租金是四份訪談都提到的主因，也是 H6 最大的干擾因素。刪掉 H2 之後，H6 必須用「街區固定效果」和「是否位於主街」把租金差異吸收掉，否則 H6 量到的「歷史效果」可能只是「南邊比較貴、人也比較多」。提案書第 5.2 節與第 8.5 節已經這樣設計。
2. **兩者都要寫進研究限制。** 租金看不到、樣本只有現存店家（存活者偏誤），這兩點在簡報的限制頁要明講。評審若問「為什麼不考慮租金」，答案是「我們查證過，公開資料對這個街區有系統性缺漏，所以改用固定效果處理」，這比沒想到要好得多。

**我也檢查了其他假說要不要一起刪：**

- **H1、H3、H5 都應該保留。** 它們只需要結構化資料，而且可以最早出結果，是簡報的安全牌。
- **H6 絕對不能刪。** 它是題目的主問題（文化特徵的影響是否因業態而異）。刪了它，研究就只剩描述統計。
- **H7 保留為探索性，可以接受。** 它依賴 LLM 抽到的創立年份，如果抽到的太少就自動略過，不花額外成本。

## 2. 需要您重新確認：B1（不做 gold set）與 B3（照建議設閘門）互相矛盾

您在 B1 把 gold set 移到未來工作，但在 B3 同意「κ ≥ 0.6 才能用 LLM 特徵」。**κ 必須拿 LLM 的答案跟人工答案比，沒有人工答案就算不出 κ，閘門一也就不存在。**

您在 B1 也寫了「要規劃一段時段去觀察並驗證 LLM 找的內容是否正確或合理」。我的處理方式是把這個時段設計成**最小可行的人工抽查**，讓它同時滿足 B1 和 B3：

| | 原本的 gold set | 改成的人工抽查 |
|---|---|---|
| 筆數 | 200 | 120 |
| 每筆幾人 | 2 人獨立加 1 人裁決 | 1 人 |
| 總人力 | 約 20 小時 | 約 4 小時（4 人各約 1 小時） |
| 能算 LLM 準確率與 κ | 能 | 能 |
| 能算人與人的一致度 | 能 | 不能 |
| 能做 PPI 偏誤修正 | 能 | 能（只要是隨機抽樣） |

**關鍵只有一點：這 120 筆必須隨機抽，不能挑方便的店。** 只要做到這點，H6 的偏誤修正和閘門一都保得住。人工時間從約 20 小時降到約 4 小時，排在 11/10 上午。

如果您連這 4 小時都排不出來，那麼閘門一只能取消，所有用到 LLM 標籤的結果都要標明「未經驗證」。我不建議這樣做，因為 RQ2（LLM 抽取品質）就會完全沒有答案，而那是這個題目「生成式 AI」部分最核心的貢獻。

## 3. A9：免費 LLM 的評估

我查過 Gemini 的免費方案。它確實存在，但**瓶頸不是錢，而是每日請求數**：免費額度依專案與模型而異，各方整理的數字從每天幾百次到約 1,500 次都有，而且 2025 年底曾經被大幅調降（[第三方整理](https://yingtu.ai/en/blog/google-gemini-api-free-tier-limits-2026)）。主抽取需要約 7,500 次呼叫（2,500 個 POI × 3 次），可能要分好幾天才跑得完，而簡報只剩四天。另外，免費方案的輸入可能被用於改進模型，所以只能送公開資料。

反過來看，Claude Haiku 5.5 每百萬輸入 token 0.10 美元（[官方定價](https://platform.claude.com/docs/en/about-claude/pricing)），全量抽取約新台幣 100–150 元，用批次介面還能再打五折。

**所以我的安排是：**

- **主抽取用 Claude Haiku 5.5**：原因是時間與可靠度，不是只有 Claude 做得到。
- **免費的 Gemini 用在兩個地方**：一是第二模型交叉檢查（約 400 次呼叫），二是 RQ3 的忠實度判官（約 100–200 次）。這兩件事用量小、不趕時間，而且「用不同的模型檢查」本來就比較好。
- **本地模型**（RTX 5070 跑 7–8B 量化模型）只當所有雲端 API 都失效時的備援。

Claude API 總花費預估約新台幣 650 元，上限設 1,000 元。

## 4. A8：Places 仍然需要，而且預期幾乎免費

移除 H2、H4 之後，Places 仍提供三樣無法替代的資料：營業時間（H1）、評論數（H6 的結果變數）、官網網址（LLM 文本的入口）。

好消息是查證後發現：Nearby Search 一次請求最多回傳 20 個地點，營業時間、評論數、官網網址都屬於 Enterprise 等級欄位（[官方文件](https://developers.google.com/maps/documentation/places/web-service/nearby-search)），而 Enterprise 等級每月有 1,000 次免費額度。用網格一次把所有欄位拿齊，預估 400–800 次請求就夠，**很可能完全不花錢**。1,500 元上限只是保險。
